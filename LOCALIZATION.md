# Website languages

English is the default for new visitors and new accounts. Existing account preferences are preserved. The language picker supports English, Hindi, Gujarati and Marathi using native language names. Signed-in changes update only that user's existing `PreferredLanguage` field and authentication principal; anonymous choices use a one-year essential, HttpOnly, SameSite=Lax cookie. Language-changing POST requests require antiforgery protection and only allow local return URLs. No database migration or translation API is needed.

Application labels render on the server through `UiText`; the same catalog supplies chat, voice, feedback and location-picker messages in JavaScript. Request culture controls display dates and the HTML `lang`/Content-Language. Marathi voice recognition uses `mr-IN` when supported by the browser. New AI requests use the current account language. Existing questions, answers, custom crop names, field names and custom reminders retain their original text. Switching chat language preserves an unsent text draft in tab-scoped session storage; attached photos and pending messages must be completed or removed first.

Crop reminders, OTP/reset emails and officer-reply email wrappers follow the recipient's saved language. Daily reminder opt-in and delivery limits are unchanged. A language choice does not translate previously delivered emails or an officer's original written reply. Existing known scheme/disease catalog content has local translations; new administrator-authored content without a reviewed catalog entry remains in its original language.

`Resources/ui.tsv` contains English keys followed by Hindi, Gujarati and Marathi translations, separated by tabs. Run `python scripts/build-translations.py` after edits. The generated `ui.json` is embedded in the application assembly, including Docker releases. Razor output remains HTML encoded; JavaScript messages use textContent. Unrecognized strings fall back to the original English/source text. Brand names, chemical/product labels, identifiers and farmer-entered text are preserved.

To add another supported language, add its catalog column, extend the compiler/catalog codes and `SiteLanguage.Options`, update allowed profile/registration values, speech code and reminder date formatting, then add persistence, rendering and email tests. Do not expose a language choice until its translations are provided and verified. Language support does not change the current location catalog, India-time crop schedule or provider data coverage.

Validation includes the regression suite plus tests for anonymous/account persistence, CSRF, safe redirects, independent users, new AI language, HTML encoding and Marathi reminders. Production UI verification checks all four choices and a narrow viewport.
